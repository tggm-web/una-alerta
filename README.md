# una-alerta
Una Alerta

Sistema informativo de prevenção sobre o Rio Una, em Palmares – PE.

Sobre o projeto

O Una Alerta é um projeto desenvolvido com o objetivo de reunir informações educativas sobre prevenção e segurança relacionadas ao Rio Una, no município de Palmares, Pernambuco.

A proposta é facilitar o acesso da população a orientações preventivas, informações sobre canais oficiais de alerta e contatos úteis, contribuindo para a conscientização sobre situações de risco.

O projeto foi criado como atividade prática da disciplina, com foco no desenvolvimento de software, no trabalho em equipe e no uso de ferramentas de versionamento.

Objetivos

- Divulgar orientações preventivas relacionadas a situações de risco.
- Reunir links de canais oficiais de informação e alerta.
- Organizar contatos úteis e informações importantes.
- Desenvolver uma interface simples e acessível.
- Praticar o versionamento de código e a colaboração utilizando Git e GitHub.

Tecnologias utilizadas

- HTML5: estrutura das páginas.
- CSS3: estilização e organização visual.
- JavaScript: funcionalidades interativas.
- Git: controle de versão do código.
- GitHub: hospedagem do repositório e colaboração entre integrantes.

Como executar o projeto

1. Clone o repositório:
   
   git clone URL_DO_REPOSITORIO

2. Entre na pasta do projeto:
   
   cd una-alerta

3. Abra o arquivo "index.html" em um navegador.

Não é necessário instalar dependências para executar a versão básica do site.

Organização das branches

Para organizar o desenvolvimento, será utilizado um fluxo de trabalho baseado no Git Flow, adaptado ao tamanho do projeto.

- "main": contém a versão estável do projeto.
- "feature/nome-da-funcionalidade": utilizada para desenvolver novas funcionalidades.
- "hotfix/nome-da-correcao": utilizada para corrigir problemas urgentes na versão estável.
- "release/versao": pode ser utilizada para preparar uma versão para entrega.

As alterações desenvolvidas em outras branches deverão ser enviadas por meio de Pull Requests para revisão antes de serem incorporadas à branch principal.

Padrão de commits

Os commits deverão ser pequenos, objetivos e relacionados a uma alteração específica.

Será utilizado um padrão baseado em Conventional Commits:

- "feat:" adição de uma funcionalidade.
- "fix:" correção de um problema.
- "docs:" alteração na documentação.
- "style:" alteração visual ou de formatação sem mudança na funcionalidade.
- "refactor:" reorganização do código sem alterar seu comportamento.
- "test:" adição ou alteração de testes.

Exemplos:

git commit -m "feat: cria pagina inicial"
git commit -m "fix: corrige menu de navegacao"
git commit -m "docs: atualiza instrucoes do README"

Como contribuir

1. Atualize sua branch principal com as alterações mais recentes.
2. Crie uma branch para a tarefa que será desenvolvida.
3. Faça as alterações necessárias no código.
4. Registre as mudanças com commits objetivos.
5. Envie a branch para o GitHub.
6. Abra um Pull Request explicando o que foi alterado.
7. Solicite a revisão de outro integrante.
8. Corrija os problemas identificados e, após a aprovação, incorpore as alterações à branch principal.

Conflitos de merge deverão ser analisados e resolvidos em conjunto, preservando as partes corretas do código.

Versionamento e releases

O projeto utilizará tags para identificar versões importantes.

Exemplos de identificação:

- "v1.0.0-alpha": versão inicial de desenvolvimento, caso seja criada.
- "v1.0.0": primeira versão estável, após a conclusão e verificação das funcionalidades previstas.

As alterações relevantes serão registradas no arquivo "CHANGELOG.md".

Limitações e segurança

O Una Alerta é um sistema informativo e educativo. Ele não monitora o nível do Rio Una em tempo real e não emite alertas oficiais.

As informações sobre situações de risco devem ser confirmadas nos canais oficiais das autoridades competentes. O site não substitui orientações da Defesa Civil ou de outros órgãos responsáveis.

Os contatos e links divulgados deverão ser verificados antes de serem disponibilizados.
